# portfolio-3d — 静木銀蔵 ポートフォリオ（Three.js 建築フライスルー版）

現行サイト（https://portfolio-ginzoshizuki.vercel.app/）の**差し替え候補**。
既存サイトのコピー・配色トークンをそのまま引き継ぎ、スクロールで巨大な
コンクリート建築の中を進んでいく体験に置き換えたもの。

コンセプト：**建築の塊＝「当たり前」、裂け目から漏れる光＝「可能性」**。
既存ヒーロー動画のブリーフと同じ対応関係を、そのまま空間にしている。

---

## 動かす

```bash
npm install
npm run dev
```

| コマンド | 何をするか |
|---|---|
| `npm run dev` | Vite 開発サーバー（http://127.0.0.1:5178） |
| `npm run build` | `dist/` に本番ビルド。Vercel はこれを見る |
| `npm run build:single` | `dist-single/index.html` — 1ファイル完結版。**ダブルクリックで開ける**（サーバー不要） |

`build:single` は CSS と JS をインライン化し、ポートレートを data URI に
埋め込む。共有・確認用。本番配信は `dist/` を使うこと。

## 空間の構成（7楽章）

カメラは常に +Z 方向へ進む。z が後退する経路は作らない（スクロールを下げて
いるのにカメラが戻ると、演出ではなくバグに見えるため）。

| z | 楽章 | 内容 | 対応セクション |
|---|---|---|---|
| -110 … -8 | Approach | 広場からファサードへ接近。中央に54mの光の刃 | Hero |
| -8 … 78 | Fissure | 幅7mの切れ目を進む。頭上をリンテルが横切る | What I Do |
| 78 … 252 | Colonnade | 大列柱ホール。左右交互の4本の柱をスラローム | Works 01–04 |
| 252 … 334 | Chamber | 閉じた内室。天井のオクルスと3つのモノリスを旋回 | Beliefs 01–03 |
| 336 … 402 | Ascent | ジッグラト状の大階段を上昇 | Profile |
| 402 … 466 | Archive | 高所のデッキ。右壁に細い光のスリット列 | Writings |
| 466 … 540 | Aperture | 90mの壁が割れ、霧が光に変わる | Contact |

末端からさらに240px送ると、アイボリーの幕を挟んで広場へループする。
**到達しただけでは発火しない**（Contact に連絡先があるため）。End キーも除外。
幕を上げるのは rAF 2フレーム＋900msの保険タイマーの早い方
（rAF は非アクティブタブで止まり、幕が残ると全画面が真っ白になる）。

ポートレートは3D空間に置かず、**HTMLオーバーレイの `<img>`**（正面向き・カメラ非依存）。

### カメラ経路を触るときの必須チェック

経路は建築を**貫通しない**ことが前提。ウェイポイントを動かしたら、`#debug` を付けて
コンソールで全区間をサンプリングし、貫通がゼロであることを確認する
（過去に回廊の壁と内室の入口壁の2箇所で突き抜けていた）。`window.journey.apply()` を
任意の wp で呼んでカメラ座標を取れる。

## 構造

```
src/
├─ main.js                起動・ループ・スクロール・後処理・品質劣化
├─ lib/
│   ├─ textures.js        コンクリート/光/碑文をすべて実行時生成（画像アセット0）
│   ├─ geometry.js        スラブ生成＋UV再スケール＋マージ
│   ├─ glow.js            光の柱・光だまり・スリット・接地影・碑文デカール
│   └─ quality.js         端末判定とフレーム監視による自動劣化
├─ world/
│   ├─ architecture.js    建築本体（7楽章）
│   ├─ lighting.js        ライティング・霧・背景

├─ ui/overlay.js          HTMLパネルのフェード制御・HUD・ナビ
└─ styles/                tokens.css（既存サイトから継承）＋ overlay.css
```

### 設計上の判断（触る前に読む）

- **シャドウマップは使っていない。** 60–70m のスラブに対してシャドウマップは
  破綻するか高すぎるかのどちらかで、「裂け目から光が差す」画を作っているのは
  加算合成のクアッド（`glow.js`）の方。光の位置は演出上の都合で自由に置ける。
  接地感は `contactShadow()` で別途与えている。
- **建築は楽章ごとに1メッシュへマージ。** スラブ数が増えてもドローコールは増えない。
  代わりにスラブ個別の出し分けはできない。
- **UVはスラブ寸法で再スケール**（`geometry.js`）。しないと 60m の壁と 2m の
  ブロックで texel 密度が変わり、模様の大きさが揃わない。
- **カメラのロールは `rotateZ()` で当てる。** `rotation.z +=` は `lookAt` が
  返す Euler の分岐（z≈0 と z≈±π のどちらでも同じ姿勢を表せる）に依存して
  符号が反転する。
- **パネルの表示位置はウェイポイント番号で指定**（`data-wp="4.55,5.45"`）。
  ピクセル位置ではなく建築上の場所に紐づくので、スクロール長を変えても
  「柱01のところでカード01」が崩れない。**範囲は重ねない**（重ねると
  受け渡しの瞬間に2枚が薄く同時表示されてゴーストになる）。
- **画面の左右と world 座標の左右は逆**。カメラは +Z を向くので、
  スクリーン右は world −X を指す。`x = -20` の柱は**画面右**に出る。
  カードの左右配置やカメラの注視点を触るときは必ずここを確認する
  （2回踏んだ。`#debug` で `world.piers` を projection して測るのが確実）。
- **注視点カーブの tension は 0.18**。列柱で注視点が左右に振れるため、
  0.5 だとスプラインが各節点を大きくオーバーシュートし、カードが出る頃には
  カメラが逆側を向いていた。
- **霧と背景色は必ず一緒に動かす。** 指数霧はジオメトリしか着色しない。
  何もない方向へ飛び出す終盤では、霧だけ明るくしても画面は真っ黒になる。
- **縦画面は水平画角が壊滅的に狭い。** Three.js は垂直画角を固定して水平を
  アスペクトに従わせるため、16:9 で 79° だった水平画角が縦持ちスマホでは
  **24°** まで落ちる（望遠クロップ）。柱の番号もポートレートも画面外に消えた。
  対策は2つセットで必要：
  ① `fitFov()` で狭い画面ほど垂直画角を開き、水平40°を最低保証する
  ② ウェイポイントに `narrow` を持たせ、**縦画面では被写体を中央かつ上寄りに
     狙う**（横画面はカードが横に並ぶので敢えて軸から外す／縦画面はカードが
     下に積まれるので中央でよく、かつカードに隠れないよう上へ逃がす）

## フォールバック

WebGL が無い / `prefers-reduced-motion: reduce` の場合、`<html>` に `is-flat`
が付き、**同じ HTML が普通の縦スクロール文書として表示される**。本文は最初から
DOM にあるので、テキスト・SEO・スクリーンリーダーはこの経路でも成立する。

## 品質段階

端末で high / mid / low を判定（`quality.js`）。さらに実測 fps が 42 を切ると
① bloom を外す → ② 解像度を落とす、の順に自動で削る。
