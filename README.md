# portfolio-3d — 静木銀蔵 ポートフォリオ（Three.js 建築フライスルー版）

現行サイト（https://portfolio-ginzoshizuki.vercel.app/）の**差し替え候補**。
既存サイトのコピー・配色トークンをそのまま引き継ぎ、スクロールで巨大な
コンクリート建築の中を進んでいく体験に置き換えたもの。

コンセプト：**建築の塊＝「当たり前」、裂け目から漏れる光＝「可能性」**。
既存ヒーロー動画のブリーフと同じ対応関係を、そのまま空間にしている。

---

## 動かす

```bash
npm install
npm run dev
```

| コマンド | 何をするか |
|---|---|
| `npm run dev` | Vite 開発サーバー（http://127.0.0.1:5178） |
| `npm run build` | `dist/` に本番ビルド。Vercel はこれを見る |
| `npm run build:single` | `dist-single/index.html` — 1ファイル完結版。**ダブルクリックで開ける**（サーバー不要） |

`build:single` は CSS と JS をインライン化し、ポートレートを data URI に
埋め込む。共有・確認用。本番配信は `dist/` を使うこと。

## 空間の構成（7楽章）

カメラは常に +Z 方向へ進む。z が後退する経路は作らない（スクロールを下げて
いるのにカメラが戻ると、演出ではなくバグに見えるため）。

| z | 楽章 | 内容 | 対応セクション |
|---|---|---|---|
| -110 … -8 | Approach | 広場からファサードへ接近。中央に54mの光の刃 | Hero |
| -8 … 78 | Fissure | 幅7mの切れ目を進む。頭上をリンテルが横切る | What I Do |
| 78 … 252 | Colonnade | 大列柱ホール。左右交互の4本の柱をスラローム | Works 01–04 |
| 252 … 334 | Chamber | 閉じた内室。天井のオクルスと3つのモノリスを旋回 | Beliefs 01–03 |
| 336 … 402 | Ascent | ジッグラト状の大階段を上昇 | Profile |
| 402 … 466 | Archive | 高所のデッキ。右壁に細い光のスリット列 | Writings |
| 466 … 540 | Aperture | 90mの壁が割れ、霧が光に変わる | Contact |

末端からさらに240px送ると、アイボリーの幕を挟んで広場へループする。
**到達しただけでは発火しない**（Contact に連絡先があるため）。End キーも除外。
幕を上げるのは rAF 2フレーム＋900msの保険タイマーの早い方
（rAF は非アクティブタブで止まり、幕が残ると全画面が真っ白になる）。

ポートレートは3D空間に置かず、**HTMLオーバーレイの `<img>`**（正面向き・カメラ非依存）。

### カメラ経路を触るときの必須チェック

経路は建築を**貫通しない**ことが前提。ウェイポイントを動かしたら、`#debug` を付けて
コンソールで全区間をサンプリングし、貫通がゼロであることを確認する
（過去に回廊の壁と内室の入口壁の2箇所で突き抜けていた）。`window.journey.apply()` を
任意の wp で呼んでカメラ座標を取れる。

## 構造

```
src/
├─ main.js                起動・ループ・スクロール・後処理・品質劣化
├─ lib/
│   ├─ textures.js        コンクリート/光/碑文をすべて実行時生成（画像アセット0）
│   ├─ geometry.js        スラブ生成＋UV再スケール＋マージ
│   ├─ glow.js            光の柱・光だまり・スリット・接地影・碑文デカール
│   └─ quality.js         端末判定とフレーム監視による自動劣化
├─ world/
│   ├─ architecture.js    建築本体（7楽章）
│   ├─ lighting.js        ライティング・霧・背景
│   └─ journey.js         カメラ経路（22ウェイポイント）
├─ ui/overlay.js          HTMLパネルのフェード制御・HUD・ナビ
└─ styles/                tokens.css（既存サイトから継承）＋ overlay.css
```

### 設計上の判断（触る前に読む）

- **シャドウマップは使っていない。** 60–70m のスラブに対してシャドウマップは
  破綻するか高すぎるかのどちらかで、「裂け目から光が差す」画を作っているのは
  加算合成のクアッド（`glow.js`）の方。光の位置は演出上の都合で自由に置ける。
  接地感は `contactShadow()` で別途与えている。
- **建築は楽章ごとに1メッシュへマージ。** スラブ数が増えてもドローコールは増えない。
  代わりにスラブ個別の出し分けはできない。
- **UVはスラブ寸法で再スケール**（`geometry.js`）。しないと 60m の壁と 2m の
  ブロックで texel 密度が変わり、模様の大きさが揃わない。
- **カメラのロールは `rotateZ()` で当てる。** `rotation.z +=` は `lookAt` が
  返す Euler の分岐（z≈0 と z≈±π のどちらでも同じ姿勢を表せる）に依存して
  符号が反転する。
- **パネルの表示位置はウェイポイント番号で指定**（`data-wp="4.55,5.45"`）。
  ピクセル位置ではなく建築上の場所に紐づくので、スクロール長を変えても
  「柱01のところでカード01」が崩れない。**範囲は重ねない**（重ねると
  受け渡しの瞬間に2枚が薄く同時表示されてゴーストになる）。
- **画面の左右と world 座標の左右は逆**。カメラは +Z を向くので、
  スクリーン右は world −X を指す。`x = -20` の柱は**画面右**に出る。
  カードの左右配置やカメラの注視点を触るときは必ずここを確認する
  （2回踏んだ。`#debug` で `world.piers` を projection して測るのが確実）。
- **注視点カーブの tension は 0.18**。列柱で注視点が左右に振れるため、
  0.5 だとスプラインが各節点を大きくオーバーシュートし、カードが出る頃には
  カメラが逆側を向いていた。
- **霧と背景色は必ず一緒に動かす。** 指数霧はジオメトリしか着色しない。
  何もない方向へ飛び出す終盤では、霧だけ明るくしても画面は真っ黒になる。
- **縦画面は水平画角が壊滅的に狭い。** Three.js は垂直画角を固定して水平を
  アスペクトに従わせるため、16:9 で 79° だった水平画角が縦持ちスマホでは
  **24°** まで落ちる（望遠クロップ）。柱の番号もポートレートも画面外に消えた。
  対策は2つセットで必要：
  ① `fitFov()` で狭い画面ほど垂直画角を開き、水平40°を最低保証する
  ② ウェイポイントに `narrow` を持たせ、**縦画面では被写体を中央かつ上寄りに
     狙う**（横画面はカードが横に並ぶので敢えて軸から外す／縦画面はカードが
     下に積まれるので中央でよく、かつカードに隠れないよう上へ逃がす）

## フォールバック

WebGL が無い / `prefers-reduced-motion: reduce` の場合、`<html>` に `is-flat`
が付き、**同じ HTML が普通の縦スクロール文書として表示される**。本文は最初から
DOM にあるので、テキスト・SEO・スクリーンリーダーはこの経路でも成立する。

## 品質段階

端末で high / mid / low を判定（`quality.js`）。さらに実測 fps が 42 を切ると
① bloom を外す → ② 解像度を落とす、の順に自動で削る。

サーバーを1本立てれば切り替えずに見比べられる。**

```bash
npm install

```

| URL | 版 | 何をしているか |
|---|---|---|
| `http://127.0.0.1:5178/` | **建築フライスルー** | 現在の本番。スクロールでコンクリート建築を進む |

# Lens Space（`experiment-space`）

スクロールしない1画面。10枚の「レンズ」（事業・思想・経歴・発信・連絡先）が板として浮かび、
**隊形を4つから選んで組み替える**。板をクリック／タップすると詳細シートが出る。

| 隊形 | 横画面 | 縦画面 |
|---|---|---|
| 環 Ring | XZ平面の輪。放射状に外を向く | **YZ平面の縦回転ホイール**（下記） |
| 螺旋 Helix | Y軸まわりの螺旋。常にカメラを向く | 半径を絞って縦に伸ばす |
| 格子 Grid | 4列。全件一覧 | 2列 |
| 散逸 Drift | 決定的ハッシュによる散乱 | 横を絞る |

Obys との一番の違いは **`.mobile-blocker` を置かないこと**。向こうはモバイルを丸ごと拒否している。

## 縦画面（ここが本体）

Three.js は垂直画角を固定して水平をアスペクトに従わせる。390px 幅では水平が望遠まで狭まるので、
フライスルー版と同じく `MIN_H_FOV` で水平46°を最低保証している。**だがそれだけでは足りなかった。**

横に広い隊形（環）は、幅を収めるためにカメラが下がり、**カードが画面高の12%まで縮んだ**（実測）。
対策は画角ではなく隊形そのもの：**縦画面では環をYZ平面に倒し、縦回転するホイールにする**。
幅を1枚ぶんしか使わないのでカメラが寄れて、手前のカードが画面幅の過半を占める。
このとき回転軸も変わるので、`layout.axis === 'x'` では**上下スワイプが回転**・左右は微小な首振りに割り当てる。

## 触る前に読む

- **カメラ距離はカードごとに解く**（`scene.js` の `frame()`）。バウンディング球で枠取りすると、
  環のような「平たい円盤」に対して高さぶんの余白まで確保してしまい、画面の2/3が空いた。
  各カードの x・y・z から必要距離を出して最大値を取るのが正しい。
- **平面グリッドを自由回転させてはいけない。** 板は `DoubleSide` だが、裏返ると文字が鏡像になるので
  正対度でフェードさせている。その結果、放置回転で格子が真横を向くと**隊形ごと消える**（実際に踏んだ）。
  `yaw: 'sway'` ＋ `yawLimit` で正対付近に留める。環と螺旋は常に正対するので自由回転でよい。
- **板の絵は実行時生成**（`plate.js`）。画像アセットは0。配色モードを変えると描き直す。
  フォントが揃う前に描くと**フォールバック書体がテクスチャに焼き付いて後から直らない**ので、
  `document.fonts.ready` を待ってから生成する。
- **和文の折り返しは3段構え**（`plate.js` の `wrap`）。
  ① 空白・字種境界・読点で切れるならそこで切る（`一般社団法人 / e-donuts`）
  ② 切れないなら1文字単位に落とす
  ③ どちらも「同じ行数を保てる最小幅」を二分探索して行長を揃える
  貪欲法だけだと `合同会社BWH総 / 合研究所` のように熟語を割る。逆に最小幅だけを狙うと
  `一般社団法 / 人 e-donuts` になる。**両方いる。**
- **`position: fixed` の中央寄せに `left: 50%` を使わない。** fixed 要素は `left` から右端までが
  シュリンク幅の上限になるので、390px 幅でスイッチャーが195pxに潰れて4つ目が切れた。
  `left:0; right:0; margin-inline:auto; width:max-content` にする。
  なお `margin-inline` は**ショートハンドの `margin: 0` より後に書く**（打ち消される）。
- **フォールバックでは `height:100%` と `overflow:hidden` の両方を外す。** 片方だけだと
  文書が1画面ぶんで止まってスクロールできない。

## フォールバック

WebGL 無し / `prefers-reduced-motion: reduce` では `.is-gl` を付けず、
**同じ HTML がそのまま縦スクロールの記事一覧になる**（実測 3319px・10件）。
`.lens` 要素が唯一の正で、ギャラリーは起動時にそれを読んでいるだけなので、
**内容を足すときは `gallery.html` の `<article class="lens">` を1つ増やすだけでよい**。
スキップリンクはクリップ領域にフォーカスを送るのではなく、`.is-gl` を外して文書表示に切り替える。

## 検証済み / 未検証

- 検証済み（Playwright・1440×900 と 390×844）：4隊形すべての描画、配色2モード、
  タップ→詳細シート（02 Kyobo で確認）、折り返し10件、フォールバックのスクロール、本番ビルド
- **未検証：実機スマホでのタッチ操作と fps。** ピンチズームと慣性は合成イベントでしか触っていない。

# Paper Space（`paper-space`）

## 何であるか

長い縦スクロール（実測 12712px ≒ 14画面）。現行7セクションをそのまま、
**紙・活字・書物**の写真で組んだもの。芯の一文は **"Another reading was always possible."**

版面の文法は Izanami から取っている：章まるごとの全面写真／左端の縦組みラベル／
英字セリフの大見出し＋和文明朝／右端から切れて出るプレート写真／全面に流れる紙埃。

## この版だけ WebGL を使っていない

3つの版で意図的にエンジンを変えてある：

| 版 | エンジン | JS（gzip） |
|---|---|---|
| `/`（main） | Three.js 建築フライスルー | 145.78 kB |
| `/gallery.html`（experiment-space） | Three.js フルイドギャラリー | ~7 kB＋three |
| `/paper.html`（このブランチ） | **素の DOM/CSS** | **1.19 kB** |

雰囲気を作っているのは写真そのものなので、WebGL を足しても得るものが少ない。
代わりに rAF 1本で埃・パララックス・進捗を回し、リビールは IntersectionObserver に任せている。
品質段階（`quality.js`）も不要。**モバイルで最も軽いのはこの版**。

## 素材

`public/paper/` に webp 18枚（計1.2MB）。**どの素材がどの章か、なぜ文字が全部読めないのかは
`public/paper/ASSETS.md` に書いてある**。カットを足すときは必ず読むこと。

## 触る前に読む

- **プレートの中央寄せは `translate`、パララックスは `transform`。** 両方 `transform` に
  書くと、rAF が毎フレーム `translateY(-50%)` を消して、全プレートが自分の高さの半分だけ
  下にずれる。
- **埃レイヤーは `repeat` させない。** 写真なので端が繋がらず、画面の真ん中に十字の継ぎ目が出た。
  `background-size: cover` で 150% のボックスを覆わせる。
  粒が大きいので**不透明度は 0.15 / 0.09 まで落とす**（上げるとレンズについた水滴に見える）。
- **`margin-inline: auto` はショートハンドの `margin: 0` より後に書く。** このリポジトリで2回踏んだ
  （gallery のヒント、paper の SCROLL）。`position: fixed/absolute` の中央寄せに `left: 50%` を
  使わないのも同じ理由（幅が残り半分に制限される）。
- **見出しの measure はブロックではなく行に掛ける。** ラッパーに `max-width: 22ch` を掛けたら
  和文リードまで巻き込まれて「もう少 / しの風通しを。」で割れた。
- 背景は必ずスクリムの下に置く。素材は単体で読める明るさで撮ってあるので、生のままだと文字が沈む。

## 検証済み / 未検証

- 検証済み（Playwright・1440×900 と 390×844）：全14ブロックの描画、画像の遅延読込、
  縦画面でのプレートと本文の非重なり・横スクロールなし、時計、進捗、本番ビルド
- **未検証：実機スマホでの fps とスクロールの感触**、および `prefers-reduced-motion` の実挙動
- Writings は現行サイト同様「準備中」のまま
